# TaskBehaviour — инструкция по настройке

Документ описывает **каждое поле** списка `TaskBehaviour` и **каждый ключ** JSON в них: структуру,
допустимые значения, вариант по умолчанию и пример.

> Формулировка «значение по умолчанию» ниже означает поведение при **отсутствии ключа**.
> Если ключ не задан — ничего «из коробки» не подставляется: карточка просто завершает задачу
> по нажатию кнопки (см. [§4 Порядок обработки](#4-порядок-обработки-нажатия)).

---

## 1. Список `TaskBehaviour` (SharePoint)

Путь: сайт `obrazceo` → список **`TaskBehaviour`**.

| Поле (InternalName) | Тип | Обязательно | Назначение |
|---|---|---|---|
| `Title` | Строка | ✅ | **Тип контента задачи.** Рекомендуется **точное** совпадение с `ContentType.Name` (например, `Исправление проблемной ЕО`). Служебные значения `*` / `_default` / `default` — «общая запись» для всех типов контента без своей записи. Как находится запись — см. [§1.1](#11-как-сопоставляется-title-и-тип-контента) |
| `Behaviour` | Многострочный текст (JSON) | ➖ | Поведение: какие поля показать, спрашивать ли подтверждение, какая анимация. См. [§3](#3-behaviour) |
| `StylingResultButton` | Многострочный текст (JSON) | ➖ | Внешний вид **кнопок результата** (`Найдена`, `Исправлено`, …). См. [§5](#5-stylingresultbutton) |
| `StylingActions` | Многострочный текст (JSON) | ➖ | Внешний вид **служебных кнопок**: «Взять в работу», «Сохранить», «Отмена», «Подтвердить». См. [§6](#6-stylingactions) |
| `Enabled` | Да/Нет | ➖ | Запись читается только при `Enabled = Да` (пусто = `Да`) |
| `Description` | Многострочный текст | ➖ | Комментарий для администратора, фронтом не используется |
| `Modified` | Служебное | — | Используется для инвалидации кэша |

### 1.1 Как сопоставляется Title и тип контента

```text
1. точное совпадение      ContentType.Name == TaskBehaviour.Title (без учёта регистра и пробелов)
2. частичное совпадение   совпадают основы слов, разница не более одного слова:
                          «Исправление проблемной ЕО» ⇄ «Задача исправления проблемной ЕО»
3. общая запись           Title = «*» / «_default» / «default»
4. записи нет             Behaviour не настроен → задача завершается по нажатию кнопки
```

На шаге 2 в консоль браузера пишется предупреждение:

```text
[TaskBehaviour] тип контента «Исправление проблемной ЕО» найден по частичному совпадению
с записью «Задача исправления проблемной ЕО». Рекомендуется переименовать запись
TaskBehaviour в точное имя типа контента: «Исправление проблемной ЕО».
```

**Как узнать точное имя типа контента:** открыть страницу с `?dbg=1` — в консоли строка
`[TaskBehaviour] not resolved { contentTypeName: "…", available: [...] }`. Значение
`contentTypeName` и есть точное имя, которое нужно вписать в `Title`.

**Кэш:** конфигурация живёт в `sessionStorage` 30 минут (ключи `sp:taskBehaviour:map:v2` / `sp:taskBehaviour:at:v2`).
Принудительное обновление без перезагрузки страницы:

```js
await window.__taskBehaviourForceRefresh();
```

Диагностика: `?dbg=1` в адресе страницы (или `localStorage.setItem("dbg_tasks","1")`) — в консоли
логи `[TaskBehaviour]` с полем `matchedBy`.

**Валидация:** если JSON в `Behaviour` / `StylingResultButton` / `StylingActions` некорректен,
запись помечается `ok:false`, поля из неё не применяются (приложение не падает, в UI показывается
плашка о проблеме конфигурации). Проверить можно так: в консоли браузера с `?dbg=1` смотрим
`behaviourOk` / `stylingOk` / `stylingActionsOk`.

## 2. Структура JSON: ключи верхнего уровня

Все три JSON-поля (`Behaviour`, `StylingResultButton`, `StylingActions`) — это объект,
где ключ — **значение результата** или специальный ключ.

| Ключ | Что означает |
|---|---|
| `"Найдена"`, `"Исправлено"`, `"Не исправлено"`, … | Правило для конкретного значения Result-поля. Регистр и пробелы по краям не важны: `"исправлено"` = `"Исправлено "` |
| `"_default"` | Общий фолбэк | 
| `"*"` | Синоним `_default`, проверяется **раньше** |
| `"_card"` | Только для `rf` (поля карточки). Приоритетнее `*` и `_default` |

**Приоритет выбора правила для значения:** `exact` → `*` → `_default` → правил нет.
**Приоритет для `rf` (поля карточки):** `_card` → `*` → `_default`.

## 3. Behaviour

```jsonc
{
  // Поля связанного элемента в карточке (общие для всех результатов)
  "_default": {
    "rf": [
      { "f": "THU",                   "ti": "ЕО" },
      { "f": "Recipient/SCNumberText","ti": "Получатель" },
      { "f": "Location1",             "ti": "Местоположение", "z": "body" }
    ]
  },

  // Правило для значения «Исправлено»
  "Исправлено": {
    "p": [],            // доп. поля перед завершением — нет
    "c": false,         // подтверждение не нужно
    "aa": false,        // блок «доп. действия» не показывать
    "aar": false,       // доп. действия не обязательны
    "loc": false,       // диалог «Где найдена ЕО?» не нужен
    "anim": { "type": "celebrate", "title": "Паллет исправлен", "text": "Отличная работа!", "emoji": "🎉" }
  },

  // Правило для значения «Не исправлено»
  "Не исправлено": {
    "p": [ { "f": "CommentResult", "ti": "Причина", "t": "text", "r": true } ],
    "c": true,
    "ct": "Подтверждение результата",
    "cm": "Вы уверены, что хотите завершить задачу как «Не исправлено»?",
    "ok": "Подтвердить «Не исправлено»",
    "no": "Отмена",
    "anim": "none"
  }
}
```

### 3.1 Ключи правила (одного значения)

| Ключ | Полное имя | Тип | По умолчанию | Описание |
|---|---|---|---|---|
| `p` | `promptFields` | массив | `[]` | Поля, которые нужно заполнить перед завершением. См. [§3.2](#32-p--поля-перед-завершением) |
| `c` | `requiresConfirmed` | bool | `false` | Показывать диалог подтверждения перед submit. Допустимо `"c": "inline"` — то же, что `ic: true` |
| `ic` | `inlineConfirm` | bool | `false` | **Подтверждение двумя кнопками в самой карточке** (`ok` / `no`), без диалога. Срабатывает, когда нечего заполнять: `p` пуст и `aa` = `false` |
| `ct` | `confirmTitle` | строка | `""` | Заголовок диалога подтверждения |
| `cm` | `confirmMessage` | строка | `""` | Текст диалога подтверждения |
| `ok` | `confirmOkText` | строка | `""` | Подпись кнопки подтверждения |
| `no` | `confirmCancelText` | строка | `""` | Подпись кнопки отмены |
| `aa` | `showAdditionalActions` | bool | `false` | Показывать блок «Дополнительные действия» в inline-форме |
| `aar` | `additionalActionsRequired` | bool | `false` | Доп. действия обязательны |
| `loc` | `requiresLocation` | bool | `false` | Перед submit открыть диалог **«Где найдена ЕО?»** (записывается в поле `Location1`) |
| `anim` | `animation` | строка \| объект | не задана | Анимация при submit. См. [§3.4](#34-anim--анимация-при-завершении) |
| `rf` | `relatedFields` | массив | `[]` | Поля **связанного элемента** (из `RelatedItems`) в карточке. См. [§3.3](#33-rf--поля-связанного-элемента) |

Логический тип понимает `true`, `1`, `"true"`, `"да"`, `"yes"` (регистр не важен).
Всё остальное = `false`.

### 3.2 `p` — поля перед завершением

```jsonc
"p": [
  { "f": "CommentResult", "ti": "Причина",   "t": "text",      "r": true },
  { "f": "Comment",       "ti": "Комментарий","t": "multiline", "r": false },
  { "f": "DC_THU",        "ti": "Код ТК",    "t": "number",    "r": false },
  { "f": "Zone",          "ti": "Зона",      "t": "choice",    "r": false }
]
```

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `f` | строка | — | **Обязательное.** InternalName поля в списке задач (например, `CommentResult`). Системные поля (`Status`, `PercentComplete`, `Title`, `Body`, `AssignedTo`, `ResultSearchTHU`, …) из этих значений **отбрасываются** |
| `ti` | строка | = `f` | Подпись поля в карточке |
| `t` | `text` \| `multiline` \| `number` \| `choice` | `text` | Тип ввода. `multiline` — многострочное (2–4 строки), Enter не отправляет. `number` и `choice` сейчас тоже рисуются текстовым полем (зарезервировано на будущее) |
| `r` | bool | `false` | Обязательное: без заполнения «Сохранить» покажет ошибку |

Порядок полей = порядок в массиве. В карточке поля появляются в inline-форме после нажатия
кнопки результата; значение уходит в SharePoint вместе с результатом.

### 3.3 `rf` — поля связанного элемента

Показывают данные по задаче. Источник значения — по порядку:

1. **связанный элемент** (`RelatedItems` → элемент ProblemsPallet);
2. **сама задача** — если связи нет или запрос ничего не вернул (поля `THU`, `Recipient`, `SCNumber`
   и др. докачивает `enrich.js`, они уже лежат в задаче);
3. плитка не показывается, если значение пустое или равно «ЕО отсутствует».

Запросы к связанному списку батчатся (до 30 Id) и кэшируются на 5 минут; при ошибке поля
запрашиваются по одному, «битые» поля запоминаются и больше не запрашиваются.

```jsonc
"rf": [
  { "f": "THU",                    "ti": "ЕО" },                                  // в шапке
  { "f": "Recipient/SCNumberText", "ti": "Получатель" },                          // lookup: Поле/Подполе
  { "f": "Location1",              "ti": "Местоположение", "z": "body" },         // перед описанием
  "DC_THU"                                                                        // короткая запись
]
```

| Ключ | Тип | По умолчанию | Описание |
|---|---|---|---|
| `f` | строка | — | **Обязательное.** Имя поля. Поддерживается путь `Поле/Подполе` для lookup (`Recipient/SCNumberText`) |
| `ti` | строка | = `f` | Подпись плитки |
| `z` | `header` \| `body` | `header` | Где показать: `header` — плитки в шапке карточки; `body` — **чип перед описанием** |

Допустимые сокращения: `f` = `field` = `name`, `ti` = `title`, `z` = `pos` = `zone`
(`body` = `b` = `description`). Короткая запись — строка вместо объекта: `"rf": ["THU", "DC_THU"]`.

### 3.4 `anim` — анимация при завершении

```jsonc
"anim": "celebrate"                       // короткая запись
"anim": "sherlock"
"anim": "none"
"anim": { "type": "celebrate", "title": "Паллет исправлен", "text": "Отличная работа!", "emoji": "🎉" }

// Sherlock со своим текстом и эмодзи (сценарий «заявка на ООБ»)
"anim": {
  "type": "sherlock",
  "title": "Создаю заявку на ООБ",
  "text": "Отправляю запрос в ООБ...",
  "emoji": "🕵️"
}
```

Если `title` / `text` не заданы — строка просто не показывается (эмодзи по умолчанию 🕵️).

| Значение | Что происходит |
|---|---|
| `celebrate` | На карточке ~1.6 с праздничная анимация (эмодзи, заголовок, текст), затем submit |
| `sherlock` | Стиль «Шерлок» (~1.6 с), затем submit. Подходит для сценария «ЕО не найдена → создаётся заявка на ООБ». ⚠️ Для результата «Не исправлено» **не использовать** |
| `none` | Без анимации — сразу submit |
| Ключ объекта `anim` | Назначение |
|---|---|
| `type` (`a`, `name`) | `celebrate` \| `sherlock` \| `none` |
| `title` (`ti`) | Заголовок на анимации |
| `text` (`message`, `subtitle`) | Подзаголовок |
| `emoji` | Эмодзи (только `celebrate`) |

Неизвестное значение игнорируется (анимации не будет).

| **не задан** | Без анимации (см. выше) |

> ⚠️ Для результата «Не исправлено» анимация не нужна — ставьте `"anim": "none"`.
> Никаких «автоматических» анимаций не существует: если ключ `anim` отсутствует — анимации не будет.

### 3.4.1 `ic` — подтверждение кнопками в карточке (без диалога)

Если включить `ic`, диалог подтверждения **не открывается**: вместо него в карточке
появляются две кнопки — `ok` и `no`.

```jsonc
"Не найдена": {
  "ic": true,               // ← подтверждение в карточке
  "ok": "Создать заявку",   // текст кнопки подтверждения
  "no": "Отмена",           // текст кнопки отмены
  "anim": { "type": "sherlock", "title": "Создаю заявку на ООБ", "text": "Отправляю запрос в ООБ...", "emoji": "\uD83D\uDD75️" }
}
```

Что происходит:

1. Нажатие «Не найдена» → кнопки результата заменяются на **«Создать заявку»** и **«Отмена»**;
2. «Создать заявку» → проигрывается `anim` (например, sherlock) и задача завершается;
3. «Отмена» → возврат к обычным кнопкам результата, ничего не сохраняется.

Условия:

* `p` (поля ввода) пуст и `aa` != true — иначе сначала показывается форма ввода;
* `loc: true` приоритетнее `ic` — сначала откроется диалог местоположения;
* стили кнопок — из `StylingActions` по ключам `confirm` / `cancel` (см. [§6](#6-stylingactions)).

### 3.5 `loc` — диалог «Где найдена ЕО?»

```jsonc
"Найдена": { "loc": true }
```

Открывает диалог с полем местоположения (пишется в `Location1`) и блоком «Дополнительные действия».
Если `loc` не задан (или `false`) — задача завершается сразу по нажатию кнопки.

## 4. Порядок обработки нажатия

Проверки идут строго по порядку — **первое совпадение выигрывает**:

```text
1. Правил нет (нет записи для CT или нет ключа под значение) → завершить сразу
2. loc = true   → диалог «Где найдена ЕО?»
3. c   = true   → диалог подтверждения (ct / cm / ok / no)
4. p   = [...] или aa = true → inline-форма в карточке (поля + «Сохранить — <Значение>»)
5. иначе        → завершить сразу + анимация, если задан anim
```

Что происходит при завершении в любом случае:

1. На карточке оверлей **«Сохранение... / Отправляю результат и закрываю задачу...»** (минимум 500 мс);
2. `MERGE` в SharePoint: значение Result-поля, prompt-поля, `Location1`, `Status = Завершена`, `PercentComplete = 1`;
3. Обновление списка;
4. Snackbar `Задача #<Id> завершена: <Значение>`.

Карточка **не исчезает** до ответа сервера: статус оптимистично не меняется.

## 5. StylingResultButton

Цвета/вариант **кнопок результата**. Ключ — значение результата (`exact`) или `_default`.

```jsonc
{
  "_default":      { "bg": "linear-gradient(180deg, #5a67d8 0%, #434190 100%)", "c": "#ffffff", "v": "ctd" },
  "Исправлено":    { "bg": "linear-gradient(180deg, #2e7d32 0%, #1b5e20 100%)", "c": "#ffffff", "v": "ctd" },
  "Не исправлено": { "bg": "linear-gradient(180deg, #e53935 0%, #b71c1c 100%)", "c": "#ffffff", "v": "ctd" },
  "Выполнено":     { "c": "#0D47A1", "v": "out" }
}
```

| Ключ | Полное имя | Тип | Значения | Описание |
|---|---|---|---|---|
| `bg` | `background` | строка ≤ 500 | любой CSS (`#fff`, `linear-gradient(...)`, `rgba(...)`) | Фон кнопки. Автоматически добавляется hover `brightness(1.1)` |
| `c` | `color` | строка ≤ 500 | любой CSS-цвет | Цвет текста |
| `v` | `variant` | строка | `ctd` = `contained`, `out` = `outlined`, `tx` = `text` | Вид кнопки MUI |
| `i` | `icon` | строка ≤ 500 | имя иконки из списка ниже или emoji (1–4 символа) | Иконка слева от текста |

**Иконки (`i`)** — имя без регистра из списка (иначе emoji-строка до 4 символов, иначе иконки не будет):

```text
add · arrowforward · cancel · check / checkcircle · close · delete · done · edit
error / erroroutline · help · location / locationon · play / playarrow
save · search · searchoff · send · warning / warningamber
```

Пример: `"i": "checkcircle"` или `"i": "🔍"`.

**Плоский цвет тоже можно.** `bg` принимает и градиент, и обычный цвет
(`"#2e7d32"`, `rgb(...)`, `var(--...)`) — градиент уходит в `background-image`,
плоский цвет — в `background-color`.

- Принимаются и короткие (`bg`/`c`/`v`/`i`), и полные (`background`/`color`/`variant`/`icon`) имена.
- Неизвестный `v` — запись игнорируется целиком (применится `_default` или стандартный вид MUI).
- Если `StylingResultButton` не задан — кнопки рисуются стандартным синим MUI, а чип «Результат»
  окрашивается по смыслу (зелёный/красный).

## 6. StylingActions

Внешний вид служебных кнопок. Те же ключи, что в [§5](#5-stylingresultbutton), но ключи верхнего
уровня — **имена действий**:

| Ключ | Куда применяется |
|---|---|
| `takeInWork` | Кнопка **«Взять в работу»** |
| `promptSubmit` | Кнопка **«Сохранить — <Значение>»** в inline-форме |
| `promptCancel` | Кнопка **«Отмена»** в inline-форме |
| `confirm` | Кнопка подтверждения в диалоге (`ok`) |
| `cancel` | Кнопка отмены в диалоге (`no`) |
| `_default` | Фолбэк для всех перечисленных |

Работают те же ключи: `bg`, `c`, `v` (теперь и вариант — он передаётся в проп `variant`,
а не в `sx`) и `i` (иконка).

```jsonc
{
  "_default":    { "v": "ctd" },
  "takeInWork":  { "bg": "linear-gradient(180deg, #7b84ff 0%, #5a67d8 100%)", "c": "#ffffff", "v": "ctd" },
  "confirm":     { "bg": "#2e7d32", "c": "#ffffff", "v": "ctd" },
  "cancel":      { "bg": "#ffffff", "c": "#5f6368", "v": "out" },
  "promptSubmit":{ "bg": "linear-gradient(180deg, #e53935 0%, #b71c1c 100%)", "c": "#ffffff", "v": "ctd" },
  "promptCancel":{ "bg": "#ffffff", "c": "#5f6368", "v": "out" }
}
```

## 7. Готовые конфигурации

### 7.1 Минимальная (рекомендуемая стартовая)

```jsonc
// Behaviour
{
  "_default": {
    "rf": [
      { "f": "THU", "ti": "ЕО" },
      { "f": "Recipient/SCNumberText", "ti": "Получатель" },
      { "f": "Location1", "ti": "Местоположение", "z": "body" }
    ]
  }
}
// StylingResultButton
{
  "_default": { "bg": "linear-gradient(180deg, #5a67d8 0%, #434190 100%)", "c": "#ffffff", "v": "ctd" }
```

## 8. Частые вопросы и ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| Настройки не применяются | `Title` ≠ `ContentType.Name` | Сверить точное имя типа контента; включить `?dbg=1` и посмотреть `matchedBy` |
| Настройки не применяются после правки | Кэш `sessionStorage` на 30 мин | `await window.__taskBehaviourForceRefresh()` или закрыть/открыть вкладку |
| JSON «не взлетел» | Лишняя запятая, «умные» кавычки, комментарии | Проверить в любом JSON-валидаторе; в консоли с `?dbg=1` смотреть `behaviourOk` |
| Поле из `rf` не видно | Нет связи `RelatedItems` или поля нет в связанном списке | Проверить `RelatedItems` задачи и наличие поля |
| Поля из `rf` не видны **вообще** | Запись не найдена (разошлись имена) | `?dbg=1` → смотреть `[TaskBehaviour] not resolved` / предупреждение о частичном совпадении; переименовать `Title` в точное имя типа контента |
| Поля из `rf` не видны, хотя запись найдена | Нет связи `RelatedItems` **и** в самой задаче полей нет | `?dbg=1` → смотреть `[DBG:TaskCard:relatedFields:empty]`: `hasRelatedItems`, `relatedItems`, `relatedValues` |
| В шапке дублируется название задачи | Настроенных полей `rf` нет — шапка пустая | Это ожидаемо: шапка заполняется только из `Behaviour.rf`, legacy-подстановки «ТК … • ЕО …» удалены |
| Кнопка результата не изменила цвет | Ключ StylingResultButton не совпадает со значением, либо невалидный `v` | Ключи сравниваются без регистра и пробелов; `v` только `ctd` / `out` / `tx` |
| Диалог подтверждения не открывается | Не задан `c: true` | Добавить `"c": true` (и при желании `ct`/`cm`/`ok`/`no`) |
| Диалог «Где найдена ЕО?» не открывается | Не задан `loc: true` | Добавить `"loc": true` для нужного значения |
| Задача завершается без подтверждения | Для значения нет ключа в `Behaviour` | Добавить ключ с нужным значением |

## 9. Связанные поля и списки (не TaskBehaviour)

| Механизм | Где настраивается | За что отвечает |
|---|---|---|
| **Result-поле** | Поле списка задач с `TypeDisplayName = «Результирующий выбор»` и `TypeShortDescription = «Результат задачи»` | Откуда берутся значения кнопок (`Найдена`, `Исправлено`, …) для каждого типа контента |
| **`sp:AdditionalActions:Default`** | sessionStorage / настройки | Список доп. действий по умолчанию |
| **Заголовок задачи** | Поле `Title` списка задач | Формируется как `<DC_THU>_<THU>`; для завершённых задач заголовок строится по тому же принципу, что и для активных |
| **Завершённые задачи** | Автоматически | Показываются счётчиком и подгружаются страницами по 20 (кнопка «Показать ещё») |

## Диагностика полей карточки (`rf`)

Включить: **`?dbg=1`** (или `localStorage.dbg = "1"`). Логи идут в консоль браузера:

| Метка | Что показывает |
|---|---|
| `[DBG:TaskCard:relatedFields]` | найдена ли запись `TaskBehaviour` для типа контента, `matchedBy`, список полей из `rf` |
| `[DBG:TaskCard:rf:source]` | нет связи `RelatedItems` → значения берём из полей самой задачи |
| `[DBG:TaskCard:rf:request]` | запрос к связанному элементу: `listId`, `itemId`, поля |
| `[DBG:TaskCard:rf:response]` | что вернул связанный список: поле → значение |
| `[DBG:TaskCard:rf:rows]` | итоговые строки с источником: `src: "related"` (связанный элемент) или `"task"` (поля задачи) |
| `[DBG:TaskCard:rf:zones]` | что ушло в шапку, а что перед описанием (`z: "body"`), в формате `Заголовок=Значение (источник)` |
| `[DBG:TaskCard:relatedFields:empty]` | поля настроены, но значений нет — причина: `hasRelatedItems`, `relatedItems`, `relatedRef` |

Живая проверка на стенде:

```bash
npx vite build --config preview/vite.config.js --ssr log-check.mjs --outDir .ssrout --logLevel error
WAIT=2000 TAG="rf:" node preview/.ssrout/log-check.mjs
```
