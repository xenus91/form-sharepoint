# UI/UX: формы задач и заявок (дизайн-система форм)

Документ фиксирует визуальные правила, по которым живут страницы форм
`#dob_tasks/<id>?list=<GUID>` — **заявка ДОБ** и **задача типа контента**
(«Результат проверки ООБ»). Обе формы обязаны выглядеть одинаково: один и тот же
порядок блоков, одни отступы, одна типографика. Источник правды по стилям —
`src/features/dob/lib/formStyles.js` (экспорты `FORM_*`, `RESULT_TOGGLE_GROUP_SX`).

## 1. Порядок содержимого страницы (сверху вниз)

1. **Шапка (sticky AppBar, 48 px).** Меню, «назад», затем
   **«Задача #<Id> · <Название задачи>»** — номер и название рядом, название
   обрезается многоточием (не ломает строку). Справа: «обновление…» (если идёт
   фоновое обновление), «Обновить», основная кнопка **«Сохранить»**.
2. **Описание задачи** (`FORM_TASK_HEAD_SX`): метка `ОПИСАНИЕ ЗАДАЧИ` + текст
   (rich-теги снимаются, абзацы сохраняются как переводы строк).
3. **Результат проверки** (только задача типа контента): группа кнопок
   результирующего выбора (`role="group"`), выбранная кнопка залита фирменным
   синим `#171c8f`.
4. **Основное поле формы** — «Описание результата проверки» (rich-текст CKEditor)
   отдельной секцией: это главное поле, оно не «прячется» среди прочих.
5. **«Остальные поля»** — секция с сеткой 1 / 3 / 4 колонки: тип ошибки,
   количество ошибок, виновные и т. п.
6. **Действия** (`FORM_ACTIONS_SX`): «Отмена» (контур) и «Сохранить» (градиент).
7. Предупреждение о незаполненных обязательных полях — над кнопками, а не в шапке.

Почему так: пользователь сначала понимает **что за задача** (номер, название,
описание), затем отвечает на **главный вопрос** (результат), затем описывает
результат, и только потом заполняет сопутствующие поля. «Остальные поля» не могут
быть первым блоком страницы.

## 2. Поля и выравнивание подписей

* Однострочные поля — `min-height: 40px` (штатная высота MUI `size="small"`),
  `border-radius: 4px`; подпись (`label`) и значение — `font-size: 13px`,
  `line-height: 1.35`. Одинаковая метрика у обоих убирает «съехавшую» подпись
  внутри инпута.
* Многострочные (`Note`) и множественные (`MultiChoice`, «Пользователь или
  группа») поля **не получают фиксированную высоту** — растут по содержимому,
  чтобы чипы/строки не обрезались.
* **Пользователь или группа** занимает широкую ячейку (`FORM_FIELD_WIDE_SX`,
  2 колонки): имя и чипы помещаются целиком, ничего не выезжает за края формы.
* Обязательность показывается звёздочкой только там, где SharePoint вернул
  `Required: true` (никаких «догадок» приложения).
* Rich-текст и длинные заметки занимают всю ширину сетки (`FORM_FIELD_FULL_SX`).

## 3. Чипы людей

* Чип содержит **только имя** (`Фамилия Имя Отчество`), без должности/департамента.
* Полные сведения (Должность, Департамент, Офис, Учётная запись) — в **карточке
  по клику** (Popover `person-details`); повторный клик закрывает карточку.
* У чипа — `max-width` и многоточие; при наведении `title` показывает
  «Имя — Должность · Департамент · Офис».
* Крестик удаляет значение и не открывает карточку.

## 4. Кнопки, состояния, цвета

| Элемент | Оформление |
| --- | --- |
| Основная кнопка | градиент `#171c8f → #10146a`, белый текст, высота 32 px |
| Вторичная кнопка | контур, тот же радиус/высота |
| Кнопки результата | `ToggleButtonGroup`, выбранная — залита `#171c8f`, высота 36 px |
| Секция | белая карточка, рамка `rgba(23,28,143,.14)`, паддинг 8–10 px |
| Заголовок секции | акцентная полоса 4×18 px + текст `font-weight: 800`, цвет `#171c8f` |
| Описание задачи | подложка `#f8f9ff` с рамкой |
| Ошибка/обязательное поле | `#c62828`, подпись под полем |

Состояния кнопок: `hover` — светлее/темнее на 6–8 %, `disabled` — без градиента
и с серым текстом, `loading` — `CircularProgress` вместо иконки и текст
«Сохранение…». Действия блокируются на время отправки (двойная отправка
невозможна).

## 5. Доступность и адаптивность

* Иконочные кнопки имеют `aria-label` («Открыть меню», «К задачам»).
* Группа кнопок результата — настоящая `role="group"`; выбранное состояние
  передаётся `aria-pressed` (MUI ToggleButton).
* Сетка полей адаптивная: 1 колонка на телефоне, 3 на планшете/десктопе,
  4 на широком экране; `minmax(0, 1fr)` + `min-width: 0` не дают содержимому
  выпирать и вызывать горизонтальный скролл (`overflow-x: hidden` у страницы).
* Контраст текста: основной — `#171c8f`/`text.primary`, второстепенный —
  `text.secondary`, ошибки — `#c62828` (≥ 4.5:1 на белом).
